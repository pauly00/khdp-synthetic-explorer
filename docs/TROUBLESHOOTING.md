# 문제 해결
## 먼저 구분할 것
- **빈 목록:** 요청은 성공했지만 조건에 맞는 저장 데이터가 없음
- **미등록:** 필요한 CSV 또는 문서가 없음
- **경로 오류:** 요청한 API 자체가 없음
- **서버 오류:** 요청은 도달했으나 처리 중 예외가 발생함
- **미리보기 연결 오류:** 브라우저가 Vite 또는 프록시까지 연결하지 못함
빈 목록과 오류를 같은 상태로 처리하면 원인을 숨기게 됩니다. 상태 코드와 응답 본문을 함께 확인하세요.
## 빈 목록
### 증상
표에 항목이 없거나 자료실에 문서가 보이지 않습니다.
### 확인
1. `GET /api/data/status`로 CSV 등록 상태와 저장 행 수를 확인합니다.
2. 검사·약물 목록이라면 검색어와 정렬을 초기화합니다.
3. 자료실 목록 `GET /api/documents`가 `[]`이면 문서가 없는 정상 상태입니다.
4. 코드 사전에 이름이 없어도 기록이 사라지지 않아야 하며 `명칭 확인 필요`로 보일 수 있습니다.
### 조치
등록되지 않은 CSV는 데이터 관리에서 등록합니다. 문서 원문은 자료실에서 README 또는 LICENSE를 등록합니다. 404를 빈 목록 또는 미등록으로 표시하도록 바꾸면 안 됩니다.
## 긴 로딩
### 증상
검사·약물 목록이나 CSV 등록이 오래 걸립니다.
### 확인
- 브라우저 개발자 도구의 Network에서 요청 URL, 상태 코드, 응답 시간을 확인합니다.
- FastAPI 로그에서 동일 요청이 처리 중인지 확인합니다.
- `measurement.csv`와 `drug_exposure.csv`는 대용량일 수 있습니다.
### 조치
검사·약물 목록은 요약 테이블 및 20개 단위 페이지네이션을 사용합니다. 검색 중에는 약 300ms 지연 후 새 요청이 발생하며 기존 요청을 취소합니다. 계속 느리면 SQLite 파일의 저장 위치·디스크 상태·요약 갱신 시간을 점검하세요. 데이터가 없을 때의 409과 오래 걸리는 200 응답은 구분합니다.
## 404 Not Found
### 증상
예: `GET /api/documents`가 404를 반환합니다.
### 확인
1. FastAPI에 해당 `@app.get(...)` 경로가 실제 등록되어 있는지 확인합니다.
2. API 서버 직접 요청으로 확인합니다.
```bash
wget -S -O- http://127.0.0.1:8000/api/documents
```
3. 화면 요청은 `api('documents')`처럼 공통 도우미를 통해 나가는지 확인합니다.
4. `vite.config.ts`의 `^(/preview/[^/]+)?/api/` 프록시와 FastAPI의 `/api/...` 경로가 모두 일치하는지 확인합니다.
### 조치
서버 직접 요청도 404면 FastAPI 경로 등록 또는 실행 중인 코드 버전을 점검합니다. 내부 요청은 200인데 미리보기에서만 404면 Vite 프록시, base 경로, 실제 실행 중인 Vite 프로세스를 확인합니다. 문서가 없는 상태는 `GET /api/documents`의 `[]`이며 404와 다릅니다.
## 413 Payload Too Large
### 증상
CSV 조각 전송 중 요청 크기 제한 오류가 납니다.
### 확인 및 조치
현재 화면은 처음 512KiB 조각으로 전송하고, 413을 받으면 최소 64KiB까지 조각 크기를 줄여 새 업로드 세션으로 다시 시도합니다. API는 700,000바이트를 초과한 조각을 거절합니다.
반복 실패하면 앞단 프록시의 업로드 제한, 네트워크 중단, 브라우저 콘솔의 실패 URL을 확인하세요. 파일 전체를 한 번에 보내는 방식으로 우회하지 마세요.
## 500 Internal Server Error
### 증상
API가 500을 반환하거나 화면에서 JSON 파싱 오류가 발생합니다.
### 확인
1. FastAPI 로그에서 traceback과 요청 경로를 찾습니다.
2. 응답의 `Content-Type`이 JSON인지 확인합니다.
3. 화면과 다운로드 API가 같은 집계 함수를 쓰는지 확인합니다.
4. SQLite 파일 경로와 읽기/쓰기 권한을 확인합니다.
### 조치
서버가 HTML 또는 일반 텍스트 오류를 반환할 수 있으므로, 화면에서 무조건 `response.json()`만 호출하지 않도록 합니다. 현재 주요 화면은 Content-Type을 확인해 오류 본문을 읽습니다. 데이터베이스를 초기화하거나 원본 CSV를 재등록하기 전에 오류 경로와 로그를 먼저 확인하세요.
## 502 Bad Gateway
### 증상
미리보기에서 nginx/Express 등의 502가 보이지만 내부 API 또는 Vite 확인은 정상일 수 있습니다.
### 확인
1. 실패한 대상이 HTML, JavaScript 파일, API 중 무엇인지 Network에서 구분합니다.
2. Vite가 실제로 `0.0.0.0:5173`에서 실행 중인지 확인합니다.
3. FastAPI는 `127.0.0.1:8000`에서 실행 중인지 확인합니다.
4. Vite가 시작 직후 종료되지 않았는지 서버 로그를 확인합니다.
5. 현재 미리보기 프로젝트 식별자와 실행 중인 작업 공간이 일치하는지 플랫폼 상태를 확인합니다.
### 조치
Vite와 FastAPI를 각각 다시 시작한 뒤 API 직접 요청과 화면 자산 요청을 따로 확인합니다. Vite 프록시는 API 요청만 전달하므로, HTML·JS가 502이면 API 라우트보다 화면 서버 또는 플랫폼 미리보기 연결을 우선 조사해야 합니다.
