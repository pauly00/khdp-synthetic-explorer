# Java·Spring·H2 이전 시험 문제 기록

## 목적과 최종 상태

이전 시험은 Python·SQLite보다 Java 기반 서버와 관계형 DB 운용에 익숙한 환경으로 옮길 수 있는지 확인하기 위해 진행했습니다. 목표는 전자정부 표준프레임워크 기반 Spring MVC, JDBC·MyBatis, 그리고 MySQL 또는 PostgreSQL을 우선 대상으로 하되, 사용 가능한 서버형 DB가 없을 경우 H2 파일 모드를 대안으로 검토하는 것이었습니다.

**최종적으로 이전은 취소되었습니다.** 현재 서비스는 React + TypeScript + Vite 화면, FastAPI API, SQLite 데이터베이스를 계속 사용합니다. React의 API 연결, 운영 SQLite, 원본 CSV와 문서·이력 데이터는 Spring 또는 H2로 전환되지 않았습니다. 이 문서는 과거 시험의 범위와 한계를 기록하는 개발자용 자료이며, 현재 서비스의 실행 안내는 [설치 및 실행 안내](SETUP.md)를 참고하세요.

Python에서 H2 JDBC를 호출할 브리지도 준비되지 않았습니다. | DB 경로만 H2로 바꾸는 방식으로는 연결 계층, 트랜잭션, 행 변환, 백업 및 SQLite 전용 SQL 호환 문제가 해결되지 않습니다. | JDBC 브리지, 전체 SQL 변환, 시험 DB 데이터 복제, API·집계·CSV 비교가 남았습니다. |

## 완료 수준을 구분한 해석

다음 결과는 서로 같은 의미가 아닙니다.

| 완료 수준 | 기록된 상태 | 전체 이전 완료 여부 |
|---|---|---|
| 소스 작성 | Spring MVC 이전 준비 자료와 시험용 코드가 보관되어 있습니다. | 아닙니다. |
| 빌드 성공 | Maven WAR 생성 로그와 WAR 내부 파일 목록이 남아 있습니다. | 아닙니다. |
| 서버 배포 | Tomcat 시작 메시지가 일부 기록에 있습니다. | 실제 API가 동작했다는 뜻은 아닙니다. |
| 실제 API 응답 | 보관된 요청 로그에서는 시험 요청이 404였습니다. 별도의 성공 보고는 재검증하지 못했습니다. | 아닙니다. |
| 데이터 이전과 결과 비교 | H2 단독 지속성 및 SQLite 기준값 기록은 있으나 전체 또는 일부 이전 비교 완료 증거는 부족합니다. | 아닙니다. |
| React 연결 전환 | 현재 React는 FastAPI API 경로를 계속 사용합니다. | 전환되지 않았습니다. |
| 재시작 후 유지 확인 | H2 단독 한 행의 재접속 확인만 기록되어 있습니다. | 서비스 전체의 유지 확인은 아닙니다. |

특히 **WAR 생성**과 **H2 단독 파일 저장 성공**은 각각 빌드 및 최소 DB 지속성 확인일 뿐이며, 전체 마이그레이션 완료를 뜻하지 않습니다.

## 성공·실패 보고의 불일치

기록에는 Tomcat 시작 또는 Spring 시험 API 성공이 보고된 흐름이 있으나, 보관된 요청 로그에는 HTTP 404가 남아 있고 성공한 JSON 응답을 뒷받침하는 동일 시점의 로그는 확인하지 못했습니다. 따라서 다음 중 어느 보고가 최종적으로 맞는지는 근거 없이 결정하지 않습니다.

- Spring Controller가 일시적으로 정상 응답했는지
- 다른 컨텍스트 경로 또는 다른 서버 인스턴스를 요청했는지
- 설정 변경 뒤 응답이 다시 404로 바뀌었는지
- 세션 변경으로 시험 도구·서버·경로를 다시 찾지 못했는지

이 불일치는 **서버 배포 또는 단일 API 성공 보고만으로 전체 이전을 진행하지 않아야 했던 이유**로 기록합니다.

## 제한 사항의 구분

### 1. 기본 도구 미설치

초기 Java, Maven, Tomcat 명령이 기본 제공되지 않았던 상태는 확인됩니다. 그러나 후속 기록에는 프로젝트 전용 JDK로 Java 컴파일·실행이 성공한 내용이 있으므로, 이를 “모두의 AI 실험실에서는 Java를 사용할 수 없다”는 결론으로 확대할 수 없습니다.

### 2. 다운로드와 네트워크 문제

Maven Central을 통한 일부 의존성·도구 다운로드는 성공했지만, Tomcat 관련 시도에서는 HTTP 404와 원격 호스트 연결 거부가 기록되었습니다. 이는 시도한 주소·시점·네트워크 조건의 문제이며, 플랫폼 전체의 네트워크 정책이나 특정 배포처 접근 정책은 확인하지 못했습니다.

### 3. 세션·경로 유지 문제

시험 도구가 프로젝트 내부의 별도 위치에 있었고, 후속 작업에서 동일한 실행 경로·환경 변수·실행 중인 서버를 다시 찾거나 재현하지 못한 정황이 있습니다. 세션 변경 뒤 파일 또는 프로세스가 어떻게 유지되는지는 기록 확인 불가입니다.

### 4. Spring 설정·라우팅·미구현 API

WAR가 만들어졌어도 Controller 탐색, Servlet 설정, 컨텍스트 경로, 요청 매핑과 실제 JSON 응답은 별도로 검증해야 합니다. 보관된 404는 이 계층 중 하나 이상 또는 API 구현 범위가 완결되지 않았음을 나타내지만, 단일 원인을 확정할 근거는 부족합니다.

### 5. FastAPI–H2 연결 계층과 SQL 호환

FastAPI는 Python 프로세스이며 현재 `sqlite3` API, `sqlite3.Row`, SQLite 백업 기능, `PRAGMA`, `INSERT OR REPLACE`, `strftime`, `julianday`, `GROUP_CONCAT`, SQLite `date()` 등의 사용에 묶여 있습니다. H2 JDBC 드라이버를 Java에서 쓸 수 있었다는 사실만으로 Python FastAPI가 H2를 읽고 쓸 수는 없습니다. JDBC 브리지와 데이터 접근 계층 교체, SQL 호환 작업이 별도로 필요했습니다.

### 6. 내부 운영 정책 미확인

플랫폼의 장기 프로세스 유지, 외부 네트워크 허용 범위, 파일 보존, 포트 노출, 패키지 설치 정책은 이 시험 기록만으로 확정할 수 없습니다. 문서에는 확인된 명령 결과와 서비스 코드 상태만 기록하며, 내부 운영 정책을 추정하지 않습니다.

## 향후 별도 환경에서의 재시도 체크리스트

이 체크리스트는 실행 지침이 아니라 재시도 전 판단 기준입니다. 현재 프로젝트에서 실행하지 않습니다.

### 시작 전 판단

- [ ] 현재 FastAPI·SQLite 구성에서 해결되지 않은 실제 요구가 있는지 먼저 확인한다.
- [ ] 이전의 기대 효과, 보존해야 할 데이터, 허용 가능한 중단 시간과 되돌리기 기준을 합의한다.
- [ ] 운영 SQLite와 원본 CSV를 보존하고, 시험은 별도 작업 공간과 별도 DB에서만 시작한다.

### 실행 환경 준비

- [ ] 대상 OS와 CPU에 맞는 JDK를 고정하고 `java`, `javac` 실행을 기록한다.
- [ ] Maven과 선택한 전자정부 표준프레임워크·Spring 버전의 호환성을 확인한다.
- [ ] 호환되는 Tomcat 버전과 실제 배포·로그 확인 절차를 준비한다.
- [ ] MySQL 또는 PostgreSQL의 연결 정보와 영구 저장소를 우선 준비한다. H2는 대안으로만 검토한다.
- [ ] Maven 의존성, JDBC 드라이버와 필요한 저장소에 접근 가능한지 한 번 확인한다.
- [ ] 실행 경로, 환경 변수, 도구 위치, 서버 로그 위치를 문서화해 세션이 바뀌어도 재현 가능하게 한다.

### 작은 범위부터 검증

- [ ] 시험 API 하나를 Controller에서 직접 JSON 200으로 응답하게 하고, 컨텍스트 경로와 요청 매핑을 확인한다.
- [ ] 한 개 테이블을 대상 DB로 복사해 행 수·기본 키·대표 값을 비교한다.
- [ ] 조건별 집계 하나를 양쪽에서 실행해 동일 조건의 결과와 CSV 내용을 비교한다.
- [ ] 문서·이력·업로드 같은 쓰기 기능은 별도 시험 DB에서 검증한다.
- [ ] API별 오류 형식, 상태 코드, 페이지네이션, 대용량 업로드를 기존 화면 기대값과 비교한다.

### 전환 판단

- [ ] 모든 API의 실제 HTTP 응답을 확인한다.
- [ ] React 연결은 API 호환성·데이터 비교·쓰기 검증이 끝난 뒤에만 바꾼다.
- [ ] 서버 재시작 뒤 데이터 유지와 핵심 API를 다시 확인한다.
